# ADR-014. Biblioteca de cifrado por flujos

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | El archivo debe cifrarse mientras llega, sin cargarlo completo en memoria ni dejarlo sin cifrar en disco. Los planes admiten archivos de hasta 5 GB. |
| Drivers | DRV-011 |
| Alternativas | Tink Streaming AEAD; cryptography con AES-GCM por fragmentos y nonce por bloque; plan B: cifrar el archivo completo con tope de tamaño por plan. |
| Decisión | Tink 1.16.1 con Streaming AEAD AES256_GCM_HKDF_1MB. Cada caso tiene su propia llave de Tink, envuelta con RSA-OAEP-256 por la llave maestra. El texto cifrado lleva como datos asociados el identificador del caso y el de la evidencia. La huella SHA-256 se calcula en la misma pasada del cifrado. La subida de API-030 se lee por flujo con el analizador incremental de python-multipart, desde un endpoint def. |
| Justificación | La prueba técnica TT-006 lo demostró: Tink detecta un byte alterado, un archivo cortado, fragmentos reordenados y datos asociados de otro caso, y nunca entrega bytes sin verificar. La versión hecha a mano con cryptography no detecta un archivo cortado en el borde de un fragmento; corregirlo exige diseñar una construcción criptográfica propia. Cifrar 2 GiB usó menos de 8 MiB de memoria extra. En Linux, el sistema de producción, Tink cifra con huella a 872 MiB/s en el equipo de desarrollo. Tink tiene paquetes para Python 3.14 en Windows y Linux y un formato documentado. Resultados completos en backend/spikes/tt006/README.md. |
| Consecuencias positivas | Memoria constante en subidas grandes; ningún archivo sin cifrar en disco; un objeto cifrado movido a otro caso o a otra evidencia no se puede descifrar. |
| Consecuencias negativas | En Windows, el paquete de Tink cifra a unos 90 MiB/s, lo que solo afecta el entorno de desarrollo. Tink no publica tipos y necesita una excepción en mypy. La llave de caso ocupa 131 bytes en lugar de 32, y envuelta con RSA de 3072 bits ocupa 384 bytes. |
| Riesgos | Al descifrar, los fragmentos verificados se entregan antes de detectar uno alterado: la descarga debe tratar un error a mitad de camino como fallo. La envoltura con Key Vault real se prueba en TT-007. RSK-02 queda mitigado. |
| Fecha y responsables | 23/10/2026 propuesto; 26/10/2026 aceptado. Juan Diego Acevedo Calderon |
