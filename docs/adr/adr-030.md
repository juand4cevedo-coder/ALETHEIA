# ADR-030. Pantallas descargadas por ruta, con descarga anticipada

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | Toda la interfaz salía en un solo archivo de JavaScript de 489 kB (151 kB comprimido). Quien abría la página de inicio descargaba también el registro, el ingreso, el espacio de trabajo y el texto completo de las cuatro políticas, aunque no fuera a usarlos. Cada pantalla que se agregue en los Sprints 4 a 6 haría crecer esa primera descarga. |
| Drivers | DRV-006, DRV-008 |
| Alternativas | Mantener un solo archivo; dividir por ruta sin descargar nada por adelantado, con una pausa visible al abrir cada pantalla; renderizar en el servidor, que exige otro proceso en producción. |
| Decisión | La página de inicio y su marco van en el archivo principal, porque son la entrada más común. Precios, las políticas, el marco de acceso y cada pantalla de acceso y del espacio de trabajo se cargan con el `lazy` de React Router, desde las funciones de `src/routes/lazyRoutes.ts`. Cuando el sitio público ya está en pantalla y el navegador queda libre, `prefetchLikelyNext` descarga precios, el marco de acceso, el ingreso y el registro; con el ahorro de datos activado no descarga nada. |
| Justificación | El archivo principal baja a 307 kB (96 kB comprimido), un 37 % menos. Lo que alguien abre después del inicio ya está en el navegador cuando hace clic, así que la división no agrega esperas. Los archivos nuevos llevan su huella en el nombre y Caddy los guarda un año, como los demás. |
| Consecuencias positivas | Las pantallas nuevas no pesan sobre la página de inicio. Un cambio en una pantalla solo invalida su propio archivo en el navegador de quien ya visitó el sitio. |
| Consecuencias negativas | Quien abre directamente una pantalla distinta del inicio, por ejemplo el enlace de un correo, espera dos descargas en lugar de una. Las pruebas montan el enrutador y esperan a que la pantalla llegue antes de revisarla. |
| Riesgos | Que un despliegue borre un archivo que una pestaña abierta todavía pide. La imagen web contiene todos los archivos del build, y una pestaña con un despliegue viejo se recupera al recargar. |
| Fecha y responsables | 05/11/2026, Juan Diego Acevedo Calderon |
| Decisión que reemplaza / es reemplazada por | Ninguna. Complementa ADR-021. |
