# ADR-059. Autoridades públicas de sellado de tiempo en producción

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | ADR-015 eligió DigiCert y Sectigo para la técnica de sellado, pero la dependencia DEP-04 (#149) seguía abierta: faltaba decidir si esas autoridades públicas sirven para el uso documental de ALETHEIA en producción o si había que contratar un proveedor. El trabajador ya pide un sello por cada evidencia (tarea `tsa_stamp`), así que la decisión rige sobre algo que está en uso. |
| Drivers | DRV-001, costo cero mientras el producto empieza, verificación independiente con OpenSSL y continuidad del servicio. |
| Alternativas | Mantener DigiCert y Sectigo (servicios públicos y gratuitos); contratar el estampado cronológico de una entidad acreditada ante ONAC; contratar una autoridad comercial RFC 3161 con acuerdo de nivel de servicio. |
| Decisión | El responsable del servicio acepta las autoridades públicas para producción: DigiCert (`http://timestamp.digicert.com`) como principal y Sectigo (`http://timestamp.sectigo.com`) como respaldo, sin autenticación ni costo. El sello se guarda tal como llega, con la evidencia, y viaja en el paquete de preservación. Las raíces fijadas en `backend/app/adapters/raices_sellado.pem` (DigiCert Assured ID Root CA y USERTrust RSA Certification Authority) son las únicas que se aceptan al verificar. |
| Justificación | Los dos servicios siguen el estándar RFC 3161, sus sellos se verifican con `openssl ts -verify -data` contra el archivo original (TT-006) y sus raíces vienen en los sistemas operativos comunes, así que un perito los revisa sin depender de ALETHEIA. Los términos, la página de seguridad y el informe de cada paquete ya dicen que no son entidades de certificación acreditadas en Colombia. |
| Consecuencias positivas | Ningún costo fijo, ningún contrato que renovar y la misma verificación pública para cualquier tercero. Cambiar de autoridad sigue siendo un cambio de configuración (ADR-010). |
| Consecuencias negativas | No hay acuerdo de nivel de servicio ni soporte: si las dos autoridades fallan, el sello queda pendiente y se reintenta. La política de Sectigo para firma documental (CP/CPS de Document Signing, versión 1.0.7) limita el uso de sus autoridades públicas; el responsable acepta ese riesgo y Sectigo queda solo como respaldo. |
| Riesgos | Que una autoridad cambie su cadena, como anunció DigiCert para septiembre de 2026: si la verificación empieza a fallar, se agregan las raíces nuevas a `raices_sellado.pem`, se corre la prueba de sellado real y se despliega. Que una autoridad restrinja el acceso: se cambia la URL por la de otra autoridad pública o por un proveedor contratado. Que un caso exija respaldo institucional: el abogado puede llevar el mismo archivo a una entidad acreditada, y la huella coincide. |
| Fecha y responsables | 25/11/2026, Juan Diego Acevedo Calderón |
| Decisión que reemplaza / es reemplazada por | Complementa a ADR-015 y cierra DEP-04. |
