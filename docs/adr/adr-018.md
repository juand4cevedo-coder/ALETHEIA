# ADR-018. Publicación y despliegue a producción por SSM con etiquetas firmadas

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado. ADR-019 reemplaza su regla de antigüedad de versiones. |
| Contexto | TT-008 debe publicar aletheia.sbs con HTTPS y un despliegue automático que exija aprobación manual y vuelva atrás si algo falla. La política de control de servicios del plan gratuito de AWS no se puede modificar y niega crear proveedores de identidad, así que GitHub Actions no puede entrar a AWS con OIDC. El puerto 22 solo está abierto a la IP del administrador, y abrirlo a los rangos de GitHub expondría SSH a internet. Hay un solo desarrollador y la Etapa 2 cierra el 2 de noviembre. Además, Python 3.14.9 y uv 0.13.5, ya usados en desarrollo y en la CI, se publicaron hace menos de 14 días. |
| Drivers | DRV-004, DRV-007, DRV-008, DRV-009 |
| Alternativas | SSH desde GitHub con el puerto 22 abierto a sus rangos; un runner propio dentro de la instancia; que la instancia revise GHCR y se actualice sola; OIDC con un rol de IAM (negado por la política del plan); SSM Run Command con el documento `AWS-RunShellScript`; SSM Run Command con un documento propio. |
| Decisión | Se publica al subir una etiqueta `vX.Y.Z` firmada sobre main. El workflow `publicar.yml` comprueba que la etiqueta coincida con la versión del código, construye las imágenes de la API y de Caddy para linux/amd64, las publica en GHCR y despliega por digest, nunca por etiqueta. El despliegue corre en el entorno production, con aprobación manual y limitado a etiquetas `v*`. Usa la llave del usuario de IAM `aletheia-github-deploy`, que solo puede enviar el documento propio `aletheia-desplegar` a `aletheia-prod` y leer su resultado. El documento valida cada parámetro con un patrón, comprueba la firma de la etiqueta con `git verify-tag` contra `/etc/aletheia/firmantes-permitidos` y ejecuta `infra/prod/desplegar.sh`: migraciones, contenedores y salud por HTTPS desde la misma máquina, con vuelta automática a la versión anterior si algo falla. Después, una prueba de humo desde internet revisa salud, cabeceras, redirecciones y orígenes, y si falla pide revertir. Las migraciones nunca se revierten: cada una se escribe para que la versión anterior de la API siga funcionando (primero se amplía el esquema y en una versión posterior se retira lo que sobra). Caddy sirve todo bajo el mismo origen con las cabeceras de seguridad, redirige HTTP y www al dominio principal con redirección permanente y no anuncia HTTP/3. Los contenedores corren sin root, con sistema de archivos de solo lectura, sin capacidades de Linux y en dos redes separadas. Toda versión de software que entra al proyecto debe tener más de 14 días de publicada. Se exceptúan Python 3.14.9 (21/10/2026) y uv 0.13.5 (22/10/2026), ya validados en desarrollo y en la CI y adoptados por correcciones de seguridad; la excepción vence el 04/11/2026. Las imágenes base se fijan por digest y Dependabot propone los cambios con 14 días de espera. |
| Justificación | Conserva la aprobación manual, las migraciones, la prueba de humo y la reversión dentro de lo que permite el plan gratuito, sin abrir puertos nuevos ni instalar servicios adicionales en la instancia. Con un documento propio, una llave filtrada no puede ejecutar comandos como root ni leer secretos: lo máximo que permite es volver a desplegar una versión que la CI ya publicó, y además la etiqueta debe estar firmada por el administrador. |
| Consecuencias positivas | Sin SSH desde GitHub; cada despliegue queda registrado en GitHub y en el historial de eventos de CloudTrail; la imagen que se aprueba es exactamente la que corre; volver atrás es automático; el endurecimiento queda en el repositorio y se revisa en cada PR. |
| Consecuencias negativas | La llave del usuario de IAM es de larga duración y hay que rotarla. El documento registrado en AWS es una copia de `infra/prod/ssm/aletheia-desplegar.yaml` y se actualiza a mano cuando cambia. El primer paquete de GHCR se crea privado y hay que hacerlo público una vez. Una migración que rompa la versión anterior impide volver atrás. |
| Riesgos | Filtración de la llave: solo sirve para ese documento sobre esa máquina, se rota al publicar v1.0.0 y ante cualquier sospecha (procedimiento en `docs/operacion/produccion.md`). Migración incompatible: revisión en cada PR con la regla de ampliar primero y retirar después. Que la excepción de los 14 días se vuelva costumbre: tiene fecha de vencimiento y queda registrada aquí. |
| Fecha y responsables | 30/10/2026, Juan Diego Acevedo Calderon |
| Decisión que reemplaza / es reemplazada por | Completa ADR-017 con la forma de publicar y desplegar. Su regla de antigüedad de versiones la reemplaza ADR-019. |
