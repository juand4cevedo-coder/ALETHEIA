# ADR-038. Tareas sin transacciones abiertas durante la red, idempotencia por tipo y reservas extendibles

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | La cola de `jobs` entrega cada tarea al menos una vez. El trabajador ejecutaba el manejador dentro de una transacción y el de correo llamaba a Amazon SES con ella abierta: una conexión ocupada durante una operación de red, y candados retenidos mientras el proveedor responde. Además, la clave de idempotencia evita encolar dos veces la misma tarea, pero no que su efecto externo se repita: si SES acepta el correo y el proceso cae antes de cerrar la tarea, el reintento lo envía de nuevo. La reserva de cinco minutos tampoco alcanza para las tareas largas que vienen, como sellar o armar un paquete. |
| Drivers | DRV-004, DRV-006 |
| Alternativas | Mantener la transacción y aceptar el costo; un patrón outbox con otra tabla para los correos; un proveedor con claves de idempotencia; reservas más largas para todas las tareas. |
| Decisión | El manejador recibe un `JobRun` y abre sus propias transacciones cortas con `run.open_session`; nunca llama a un servicio externo con una abierta. El de correo arma el mensaje y confirma lo que la plantilla guarda (por ejemplo, el hash del token de una invitación) antes de enviar, y envía sin transacción. Las tareas largas llaman a `run.renew_lease` entre pasos, que extiende la reserva otros cinco minutos solo si sigue siendo de ese intento; si no, lanza `LeaseLostError` y el intento se detiene sin cerrar la tarea. Cada tipo declara su idempotencia: **email_send**, al menos una vez, con un duplicado posible solo si el proceso cae entre la aceptación de SES y el cierre; el reintento de una invitación genera un enlace nuevo que reemplaza al anterior. **tsa_stamp**, idempotente por el estado de la evidencia: si ya tiene sello, no vuelve a pedirlo. **export_build**, idempotente por la fila del paquete: escribe con una clave determinista y solo marca listo una vez. **case_purge**, idempotente por `purge_case`, que devuelve la constancia existente. **payment_reconcile**, idempotente por `payment_events.gateway_event_id`. **export_expire**, **audit_anonymize** y **subscription_expire**, actualizaciones condicionales que no cambian nada la segunda vez. |
| Justificación | Separar la red de las transacciones libera conexiones y candados, y hace que lo que el correo promete, como un enlace, ya exista cuando llega. Un correo duplicado en un caso raro es aceptable; uno con un enlace que no sirve no lo es. Declarar la idempotencia por tipo obliga a pensar el reintento antes de escribir cada manejador. Extender la reserva solo cuando hace falta mantiene corta la espera ante un trabajador caído. |
| Consecuencias positivas | Se corrige la consecuencia negativa de ADR-035: el enlace de una invitación siempre corresponde a un hash ya guardado. Las tareas largas pueden durar lo que necesiten sin que otro trabajador las retome. |
| Consecuencias negativas | Los correos pueden llegar duplicados en el caso descrito. Cada manejador largo debe acordarse de extender su reserva. |
| Riesgos | Un manejador nuevo que llame a la red dentro de una transacción; lo detecta en revisión la prueba de conexiones abiertas durante el envío y la regla escrita en `app/worker/handlers.py`. |
| Fecha y responsables | 10/11/2026, Juan Diego Acevedo Calderon |
| Decisión que reemplaza / es reemplazada por | Complementa ADR-003 (cola en PostgreSQL) y ADR-024 (correo con Amazon SES), y corrige una consecuencia de ADR-035. |
