# ADR-015. Sellado de tiempo RFC 3161

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | Cada evidencia necesita un sello de tiempo de un tercero sobre su huella (INT-02), y un perito debe poder verificarlo con herramientas estándar, sin depender de ALETHEIA. |
| Drivers | DRV-001 |
| Alternativas | Autoridades públicas DigiCert, Sectigo y FreeTSA; armar la solicitud con rfc3161-client o con asn1crypto; verificar con rfc3161-client o con openssl. |
| Decisión | DigiCert como autoridad principal y Sectigo como respaldo por configuración, detrás del adaptador de sellado (ADR-010); FreeTSA se descarta. La solicitud se arma con asn1crypto sobre la huella SHA-256 del archivo tal cual, con nonce aleatorio y pedido de certificado. El sello se guarda tal como llega y se verifica con rfc3161-client contra raíces fijadas en el repositorio, después de reordenar en memoria la lista de certificados, que no está firmada. |
| Justificación | En TT-006, DigiCert y Sectigo devolvieron sellos que verifican con rfc3161-client y con openssl ts -verify -data contra las raíces de Debian. FreeTSA no verifica porque su raíz no es pública. rfc3161-client vuelve a calcular el hash de lo que recibe, así que con él se sellaría el hash de la huella y openssl no podría verificar el sello contra el archivo. DigiCert y Sectigo envían los certificados fuera del orden DER, y rfc3161-client solo los lee después de reordenarlos; una prueba comprueba que el contenido firmado no cambia. |
| Consecuencias positivas | Cualquier perito verifica el sello con openssl y el archivo original. Cambiar de autoridad es un cambio de configuración. |
| Consecuencias negativas | asn1crypto no publica versiones desde 2022 y no tiene tipos. El reordenamiento de certificados es código propio, pequeño y probado. Las autoridades públicas no son entidades de certificación acreditadas en Colombia; contratar una sigue siendo una mejora posterior que no cambia el modelo de datos. |
| Riesgos | Que la autoridad no responda: el sello queda pendiente y se reintenta según INT-02. Que la autoridad cambie su cadena: hay que actualizar las raíces fijadas. Las raíces que anclaron hoy son DigiCert Assured ID Root CA y USERTrust RSA Certification Authority; en el Sprint 4 se comprueba si DigiCert Trusted Root G4, más reciente, ancla sola la cadena de DigiCert para fijarla en su lugar. |
