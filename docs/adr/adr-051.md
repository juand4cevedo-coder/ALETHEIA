# ADR-051. Archivos estáticos por una red de distribución

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | Todo el sitio sale de una sola instancia en Ohio. Para quien visita desde Colombia, cada archivo (el JavaScript, las fuentes y las fotografías de la portada) viaja unos 450 ms hasta el servidor y vuelve. Las fotografías y el código son lo más pesado de la primera visita. |
| Drivers | Acercar los archivos al visitante sin mover la API, las sesiones ni la evidencia; poder apagarlo sin tocar código; no ampliar la superficie del CSP más de lo necesario. |
| Alternativas | Dejar todo en el servidor y aceptar la latencia; servir todo el sitio por CloudFront (obliga a tratar cookies, CSRF y descargas de evidencia en la red de distribución); un servicio de imágenes de terceros; CloudFront solo para archivos estáticos públicos en un subdominio propio. |
| Decisión | Una distribución de CloudFront en `cdn.aletheia.sbs`, con origen `aletheia.sbs`, que solo sirve `/assets/`, `/media/` y `/brand/`. Una función de CloudFront responde 404 a cualquier otra ruta. La respuesta lleva CORS solo para `https://aletheia.sbs` y `Cross-Origin-Resource-Policy: cross-origin`. El sitio la usa cuando la imagen web se construye con `VITE_CDN_URL`: Vite reescribe las direcciones de `/assets/` con `experimental.renderBuiltUrl`, un complemento reescribe las de `/media/` y `/brand/` en el `index.html`, y `config/media.ts` las compone en las imágenes. Íconos, manifiesto, HTML y API se quedan en el origen. El interruptor es la variable de repositorio `CDN_URL`, que `publicar.yml` pasa como argumento de construcción; sin ella todo sale del mismo origen. El CSP de Caddy permite `https://cdn.aletheia.sbs` en `script-src`, `style-src`, `img-src` y `font-src`. |
| Justificación | Los archivos de `/assets/` llevan huella y las imágenes son públicas: no hay nada sensible que cachear mal. Un subdominio propio evita mezclar cookies, y la función de rutas impide que la distribución sirva algo que no se quiso publicar. Mantener el interruptor en la construcción permite probar con una versión y deshacerlo con otra, sin migraciones ni cambios de infraestructura. |
| Consecuencias positivas | Menos latencia en la primera visita desde fuera de Ohio; menos tráfico y conexiones en la instancia; el primer terabyte de salida al mes entra en el nivel gratuito de CloudFront. |
| Consecuencias negativas | Un dominio más que mantener (certificado, registro DNS, distribución). Si CloudFront falla con el interruptor activo, la página se ve sin estilos ni código hasta que se publique una versión sin él. El CSP admite un origen más para scripts. |
| Riesgos | Un cambio de nombre de las rutas públicas fuera de `/assets/`, `/media/` y `/brand/` no se vería en la red de distribución: esas rutas deben seguir en el origen. Los enlaces de descarga con atributo `download` (el logotipo en Información) se dejan en el origen, porque los navegadores lo ignoran entre orígenes distintos. Si el certificado de `cdn.aletheia.sbs` no se renueva (el registro de validación DNS debe seguir creado), el sitio con el interruptor activo se rompe. |
