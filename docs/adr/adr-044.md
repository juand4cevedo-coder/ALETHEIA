# ADR-044. Formato del manifiesto de preservación versión 1

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | HU-025 debe producir un paquete que HU-026 pueda comprobar sin cuenta y sin enviar archivos al servidor. La fila `exports` conserva la huella del manifiesto, pero aún no existe un formato compartido entre el generador y el verificador. |
| Drivers | DRV-001, DRV-004 |
| Alternativas | Usar nombres originales como rutas del ZIP; generar un manifiesto distinto para cada pantalla; firmar el manifiesto con una clave de la aplicación; incluir solo las huellas de los archivos. |
| Decisión | El ZIP contiene `manifest.json` codificado en UTF-8, con `format: "aletheia-preservation-manifest"` y `format_version: 1`. Incluye `export_id`, `case_id`, `generated_at` en UTC, `scope: "file-integrity"`, `evidences` y `custody`. Cada evidencia lleva `id`, `original_filename`, `size_bytes`, `sha256` en hexadecimal minúsculo, `path: "files/<id>"`, `tsa_status` y `tsa_token_path` (solo si está sellada, `timestamps/<id>.tsr`). La custodia lleva `head_seq`, `head_sha256`, `events_path: "custody/events.json"` y `anchor_token_path` (`custody/head.tsr` o `null`). Las evidencias se ordenan por UUID ascendente. Los nombres originales son metadatos; nunca determinan una ruta del ZIP. La representación se genera con claves ordenadas, JSON compacto sin espacios superfluos, Unicode UTF-8 y un salto de línea final. `exports.manifest_sha256` es SHA-256 de esos bytes exactos. |
| Justificación | Las rutas basadas en identificadores evitan colisiones y recorridos de directorio. Una representación única permite repetir la generación y comparar su huella. HU-026 solo necesita leer la entrada `sha256` y el archivo local para responder si coinciden; no necesita confiar en el servidor ni ver el contenido del caso. |
| Consecuencias positivas | El generador de HU-025 y el verificador de HU-026 comparten un contrato versionado. Un sello pendiente queda explícito sin inventar un token. Se pueden incluir originales con nombres iguales. |
| Consecuencias negativas | El manifiesto por sí solo no prueba quién lo creó ni la autenticidad de los archivos; la interfaz debe limitarse a informar coincidencia de huellas. La comprobación de custodia y de sellos requiere los archivos y autoridades correspondientes. Los cambios incompatibles exigen una versión nueva. |
| Riesgos | Un consumidor que ignore `format_version` podría interpretar mal otro formato; debe rechazar versiones desconocidas. Un archivo puede coincidir con un manifiesto alterado; la interfaz debe explicar que la comparación no autentica el manifiesto. |
| Fecha y responsables | 16/11/2026, Juan Diego Acevedo Calderon |
| Decisión que reemplaza / es reemplazada por | Complementa ADR-012, ADR-015 y ADR-037. |
