# ADR-042. Abrir un caso: llave envuelta antes de la transacción, radicado único y datos procesales opcionales

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | HU-015 abre un caso con su identidad procesal y con su propia llave de cifrado. Hay que decidir cuándo se llama a KMS, qué entra en la cadena de custodia y cómo se evita abrir dos veces el mismo proceso. |
| Drivers | DRV-002, DRV-004 |
| Alternativas | Llamar a KMS dentro de la transacción; guardar el título y el radicado en el evento de custodia; exigir el radicado; dejar el radicado repetido a un error genérico 409. |
| Decisión | (1) La llave de datos del caso (keyset de Tink, ADR-014) se genera y se envuelve antes de abrir la transacción: ninguna llamada de red con una transacción abierta. Si KMS falla, la API responde 503 y no queda ninguna fila. (2) En una sola transacción se insertan el caso, la membresía de quien lo abre, el evento `case_created` y la entrada de auditoría `case_created` (migración 0015). (3) El evento lleva solo `key_version`: el título y los datos procesales no entran en la cadena, que es inmutable. (4) `filing_number` (23 dígitos, guardados sin espacios ni guiones), `court` y `practice_area` son opcionales (migración 0014). Un índice único parcial `(organization_id, filing_number)` impide repetir un radicado en una organización; la API lo responde con 409 y el tipo de problema `https://aletheia.sbs/problemas/radicado-repetido`. (5) `POST /api/v1/cases` exige rol propietario, administrador o abogado y correo verificado; `GET /api/v1/cases/{case_id}` responde 404 igual para un caso inexistente y para uno ajeno (RN-008). (6) `GET /api/v1/cases?status=open|closed|all&cursor=&limit=` (HU-017; 25 casos por página, 50 como máximo) lista solo los casos donde la persona es miembro, sin los que están en estado `deleting`, ordenados por última actividad descendente; la última actividad es la hora del último evento de custodia del caso. El cursor es el par (hora del último evento, id del caso) y uno ilegible responde 422. Los totales de la franja (casos por estado, evidencias, sellos pendientes y eventos) se calculan sobre todos los casos de los que la persona es miembro, con independencia del filtro y de la página. (7) Fuera de producción la llave maestra es un RSA local (`ALETHEIA_LOCAL_KEY_PATH`); en producción es `alias/aletheia-prod-maestra` en KMS y la API rechaza esa variable. |
| Justificación | Mantener una transacción abierta durante una llamada de red bloquea conexiones y filas si KMS tarda. Un dato personal escrito en la cadena no se podría corregir ni eliminar (Ley 1581 de 2012). El radicado repetido es un error que la persona puede corregir y merece un tipo propio. |
| Consecuencias positivas | Un caso nace con llave, equipo y primer eslabón de custodia, o no nace. La cadena no guarda datos personales. |
| Consecuencias negativas | Si la transacción falla después de envolver la llave, esa llamada a KMS se pierde sin dejar rastro. Los datos del caso no se editan: no existe una acción de custodia para ello. |
| Riesgos | Perder la llave local deja sin abrir los casos creados con ella; solo sirve para desarrollo. Límite de escala de la lista: ordenar por última actividad no puede usar un índice, pues el valor sale de un agregado sobre los eventos; es aceptable con cientos de casos por persona. Si crece, la salida es una columna `cases.last_activity_at` mantenida por un disparador, con su índice. |
