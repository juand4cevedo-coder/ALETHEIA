# ADR-046. Estructura del ZIP de preservación y custodia verificable

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | ADR-044 fija `manifest.json`, pero HU-025 también debe empaquetar originales, custodia, sellos e informe sin permitir rutas basadas en nombres aportados por usuarios. El verificador independiente de ADR-037 necesita los datos exactos que entraron en cada hash de custodia. |
| Drivers | DRV-001, DRV-004 |
| Alternativas | Copiar los nombres originales como rutas; guardar solo el hash final de custodia; construir todo el ZIP en memoria; usar un formato de custodia que reformatee `details` al verificar. |
| Decisión | El ZIP contiene `manifest.json`, `report.pdf`, `custody/events.json`, `files/<uuid>` por evidencia, `timestamps/<uuid>.tsr` cuando su sello existe y `custody/head.tsr` cuando existe un anclaje de la cabeza. `custody/events.json` usa `format: "aletheia-custody-events"`, `format_version: 1`, `case_id` y eventos ordenados por `seq`. Cada evento conserva `seq`, `evidence_id`, `actor_user_id`, `action`, `occurred_at` UTC con microsegundos, `prev_hash`, `event_hash` y `details_jsonb_text`: el texto exacto de JSONB empleado por la serialización canónica de ADR-037. Antes de escribir, se verifica la cadena y que pertenece al caso; cada original se escribe por fragmentos y se compara con tamaño y SHA-256 del manifiesto. Las rutas y fechas de las entradas ZIP son deterministas. El destino debe permitir abortar y descartar el ZIP parcial ante cualquier error. |
| Justificación | El texto canónico de `details` evita que un verificador externo obtenga otro hash por diferencias de serialización JSON. Los UUID en las rutas evitan colisiones y recorridos de directorio. La lectura por fragmentos mantiene acotada la memoria para originales grandes. |
| Consecuencias positivas | El contrato del ZIP puede probarse sin S3 ni una autoridad de sellado. Un sello pendiente aparece como tal y no crea un archivo `.tsr` inexistente. El mismo manifiesto alimenta HU-026. |
| Consecuencias negativas | El paquete puede carecer de anclaje externo mientras DEP-04 siga abierto; en ese caso, verificar la cadena no prueba que un administrador de la base no la haya reescrito completa. El informe PDF y la publicación del ZIP necesitan sus propios pasos de generación y entrega. |
| Riesgos | Publicar un objeto parcial o un original alterado. El generador lanza un error y la tarea que lo use deberá abortar la carga; una prueba integral debe comprobar esa limpieza. |
| Fecha y responsables | 17/11/2026, Juan Diego Acevedo Calderon |
| Decisión que reemplaza / es reemplazada por | Complementa ADR-037 y ADR-044. |
