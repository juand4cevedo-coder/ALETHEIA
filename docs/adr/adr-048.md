# ADR-048. Enlace de exportación válido 24 horas con firma de la aplicación

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | HU-025 promete un enlace de descarga que vence a las 24 horas. Producción usa un rol de instancia con credenciales temporales: según AWS, una URL prefirmada de S3 deja de servir al vencer esas credenciales, aunque `X-Amz-Expires` indique 24 horas. |
| Drivers | DRV-001, DRV-004, DRV-007 |
| Alternativas | Añadir una clave permanente de IAM para firmar URLs S3; ofrecer URLs S3 que puedan fallar antes; hacer la descarga autenticada sin enlace transferible; firmar el enlace con la clave de la aplicación y servir el ZIP con credenciales vigentes del rol. |
| Decisión | Al marcar el paquete `ready`, fijar `expires_at` a 24 horas después. El enlace lleva un JWT HS256 con una subclave exclusiva de exportación, el UUID de `exports`, vencimiento y un sello HMAC del `manifest_sha256`. El token viaja en el fragmento de una ruta pública y el navegador lo borra de la dirección antes de enviarlo en el cuerpo de un `POST` de descarga, nunca como parámetro de consulta. La API comprueba firma, uso, fecha, estado `ready`, `expires_at` y huella actual antes de leer el objeto S3 con las credenciales vigentes del rol. La respuesta usa `Cache-Control: no-store`. El enlace se puede usar más de una vez durante su vigencia; la caducidad y la eliminación del objeto se gestionan por separado mediante `export_expire`. |
| Justificación | La validez de 24 horas queda bajo control de la aplicación y de la fila del paquete, sin incorporar credenciales permanentes de AWS. El fragmento no llega a Caddy ni a los registros HTTP; la API recibe el token en un cuerpo que no se registra. El sello lo invalida si el manifiesto cambia. |
| Consecuencias positivas | La renovación de credenciales del rol no acorta el plazo del enlace. El objeto no necesita ACL pública ni una URL S3 compartida. |
| Consecuencias negativas | La API transmite el ZIP y consume ancho de banda. Cerrar o rotar de emergencia la clave maestra de tokens invalida los enlaces anteriores. Quien posea el enlace puede descargarlo hasta el vencimiento, por lo que debe tratarse como una credencial temporal. |
| Riesgos | Divulgar el token en registros, historial o cabeceras; usar fragmento y cuerpo, no consulta. Entregar un ZIP vencido o parcial; comprobar la fila antes de abrir S3 y publicar solo tras confirmar el objeto completo. |
| Fecha y responsables | 17/11/2026, Juan Diego Acevedo Calderon |
| Decisión que reemplaza / es reemplazada por | Complementa ADR-027, ADR-034, ADR-038 y ADR-046 para exportaciones. |

Fuente: [AWS confirma que una URL S3 prefirmada con credenciales temporales vence cuando vencen las credenciales](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html).
