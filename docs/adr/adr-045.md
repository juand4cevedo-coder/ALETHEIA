# ADR-045. SHA-256 incremental para la verificación local

| Campo | Contenido |
| --- | --- |
| Estado | Aceptado |
| Contexto | HU-026 debe comprobar archivos de tamaño variable en el navegador, sin cuenta ni envío a la API. `SubtleCrypto.digest` requiere cargar todos los bytes en memoria. ADR-012 dejó pendiente la biblioteca incremental. |
| Drivers | DRV-001, DRV-004 |
| Alternativas | Cargar el archivo completo con Web Crypto; implementar SHA-256 propio; usar WebAssembly; calcularlo en el hilo principal con una biblioteca JavaScript. |
| Decisión | Usar `@noble/hashes` 2.4.0 (`sha256.create().update(...).digest()`) dentro de un Web Worker. Leer el `File` local en fragmentos de 1 MiB con `slice().arrayBuffer()` y comunicar solo progreso y huella. El manifiesto se interpreta según ADR-044; se rechazan versiones desconocidas. El Worker se termina al cambiar archivos o salir de la pantalla. |
| Justificación | El cálculo incremental limita la memoria al fragmento activo y mantiene libre la interfaz. JavaScript evita modificar la política de seguridad de contenido para WebAssembly. La biblioteca mantiene la API incremental y publica pruebas y auditoría de su implementación SHA-256. |
| Consecuencias positivas | El archivo nunca entra en una petición de red. La pantalla puede mostrar ambas huellas, coincidencia o diferencia y el progreso para archivos grandes. |
| Consecuencias negativas | El resultado solo compara bytes con un manifiesto aportado por el usuario; no autentica ese manifiesto. La carga del Worker añade un recurso separado. |
| Riesgos | Un manifiesto alterado puede contener la huella de otro archivo. La interfaz explica el alcance y no afirma autenticidad ni validez jurídica. |
| Fecha y responsables | 17/11/2026, Juan Diego Acevedo Calderon |
| Decisión que reemplaza / es reemplazada por | Resuelve la biblioteca pendiente de ADR-012 y usa ADR-044. |

Fuente técnica: [documentación y seguridad de noble-hashes](https://github.com/paulmillr/noble-hashes).
